# ระบบฉลากดิจิทัล อย. (Thai FDA Digital Labeling Platform)

> **ระบบสารสนเทศฉลากดิจิทัล สำนักงานคณะกรรมการอาหารและยา (อย.) กระทรวงสาธารณสุข**  
> *Interactive Functional Prototype & Architecture Specification for Government Enterprise*

---

## 📋 ภาพรวมโครงการ (Project Overview)

ระบบฉลากดิจิทัล อย. (Digital Labeling Platform) ได้รับการออกแบบและพัฒนาเพื่อยกระดับการคุ้มครองผู้บริโภคและอำนวยความสะดวกแก่ผู้ประกอบการในการจัดทำฉลากอิเล็กทรอนิกส์ตามพระราชบัญญัติอาหารและยา โดยเชื่อมโยงข้อมูลทะเบียนจากระบบ **e-Submission** เข้าสู่ระบบการจัดทำคำขอ ตรวจประเมินโดยเจ้าหน้าที่ อย. และออก **QR Code มาตรฐาน** เพื่อให้ประชาชนสามารถสแกนตรวจสอบข้อมูลผลิตภัณฑ์สุขภาพได้อย่างแม่นยำและโปร่งใส

---

## 🚀 สรุปสิ่งที่พัฒนาและส่งมอบในระบบ (Delivered Modules)

### 1. Module A: พอร์ทัลฉลากสาธารณะสำหรับประชาชน (Public / Consumer)
- **หน้าหลักและระบบสแกน (`/`)**: ค้นหาเลขสารบบ 13 หลัก, ทะเบียนยา, Newcode พร้อมทางลัดทดลองดูฉลาก 3 กรณีศึกษา
- **หน้าค้นหาฉลาก (`/search`)**: ค้นหาแบบ Real-time พร้อมตัวกรองหมวดหมู่อาหาร, ยา, เครื่องสำอาง
- **หน้ารายละเอียดฉลาก (`/verify/:newcode`)**: 
  - แสดงชื่อภาษาไทย-อังกฤษ, ภาพบรรจุภัณฑ์, ข้อมูลผู้ผลิตและสถานที่, ตารางโภชนาการ, ข้อบ่งใช้/วิธีใช้ยา
  - **สลับภาษา TH / EN** ได้ในคลิกเดียว
  - **PDF Viewer ภายในหน้าเว็บ**: เปิดอ่านเอกสารกำกับยาและผลแล็บทางการของ อย. ได้โดยไม่ต้องดาวน์โหลดโปรแกรมเสริม
  - **ปุ่มแจ้งปัญหาข้อมูลผลิตภัณฑ์**: ส่งเรื่องร้องเรียนสู่ระบบ อย. 1556
  - **แบนเนอร์แจ้งเตือนอันตรายกรณีสินค้าถูกสั่งระงับ (Suspended)**: แสดงเตือนภัยผู้บริโภคสีแดงทันทีพร้อมปุ่มโทรแจ้งสายด่วน 1556

### 2. Module B: พอร์ทัลผู้ประกอบการ (Entrepreneur Portal)
- **แดชบอร์ด (`/entrepreneur/dashboard`)**: KPI รวม, กราฟแนวโน้มการสแกนด้วย Recharts, สัดส่วนหมวดหมู่
- **ทะเบียนผลิตภัณฑ์ (`/entrepreneur/products`)**: ตรวจสอบข้อมูลที่ซิงก์จาก e-Submission (มี Guardrail ป้องกันการแก้ไขข้อมูลทะเบียนหลัก)
- **จัดการฉลากดิจิทัล (`/entrepreneur/labels`)**: สร้างร่างฉลาก (Draft), กรอกข้อมูลตามประเภท (อาหาร/ยา/เครื่องสำอาง), ดูตัวอย่าง (Preview), ส่งตรวจ (Submit), ดูบันทึกส่งกลับแก้ไข และกด **"เผยแพร่ฉลาก (Publish)"** เมื่อผ่านการอนุมัติ
- **จัดการ QR Code (`/entrepreneur/qrcodes`)**: พรีวิวและดาวน์โหลด QR Code ในฟอร์แมต **SVG (Vector)** และ **PNG** เลือกความละเอียดสำหรับงานพิมพ์บรรจุภัณฑ์ (300px - 2400px)
- **สถิติการสแกน (`/entrepreneur/analytics`)**: วิเคราะห์ยอดสแกนตามช่วงเวลา, ประเภทอุปกรณ์, เว็บเบราว์เซอร์ และพื้นที่กลุ่มจังหวัด พร้อมปุ่ม **Export Excel (.xlsx) และ CSV**
- **ตัวแทนผู้รับมอบอำนาจ (`/entrepreneur/representatives`)**: บันทึกหนังสือมอบอำนาจและตรวจสอบสิทธิผ่าน DBD

### 3. Module C: พอร์ทัลเจ้าหน้าที่ อย. (FDA Officer Portal)
- **แดชบอร์ดเจ้าหน้าที่ (`/officer/dashboard`)**: ติดตามคิวงาน, สถิติระยะเวลาพิจารณาเฉลี่ย (Turnaround Days)
- **คิวงานพิจารณาคำขอ (`/officer/queue`)**: กรองคำขอตามหมวดหมู่และสถานะ พร้อมปุ่มเปิดห้องตรวจ
- **ห้องพิจารณาคำขอ 2 คอลัมน์ (`/officer/review/:id`)**:
  - **ฝั่งซ้าย**: ข้อมูลทะเบียน e-Submission, รายละเอียดฉลาก, รูปภาพ, ปุ่มเปิดอ่านเอกสาร PDF
  - **ฝั่งขวา**: Checklist ตรวจประเมินแบบ Interactive ครบ 6 มิติ, ช่องระบุข้อเสนอแนะส่งกลับแก้ไข, ปุ่มอนุมัติ (Approve), ส่งกลับแก้ไข (Revision Required), ไม่อนุมัติ (Reject), สั่งระงับ (Suspend), หรือเปิดเผยแพร่ (Publish)
- **กำกับดูแลและระงับฉลาก (`/officer/oversight`)**: ค้นหาผลิตภัณฑ์ทั้งหมดในความดูแล และสั่งระงับฉลาก (Suspend) หรือปลดล็อก (Unsuspend)
- **รายงานราชการ (`/officer/reports`)**: ดูตัวอย่างรายงานและส่งออก Excel / CSV

### 4. Module D: คอนโซลผู้ดูแลระบบ (Administrator Portal)
- **แดชบอร์ดภาพรวมระบบ (`/admin/dashboard`)**: สถิติผู้ใช้งานและทราฟฟิก API
- **จัดการผู้ใช้งาน (`/admin/users`)**: เพิ่ม/แก้ไขผู้ใช้, เปิด/ระงับบัญชี, กำหนดบทบาท
- **ผังเมทริกซ์สิทธิ์ (`/admin/roles`)**: Interactive Permission Matrix Table จำแนก 5 บทบาทตามมาตรฐาน RBAC
- **ข้อมูลหลัก (`/admin/master-data`)**: หมวดหมู่ผลิตภัณฑ์, ประเภทเอกสารแนบ
- **สถานะการเชื่อมต่อ API (`/admin/integrations`)**: แสดงสถานะ ThaID, SKYNET, e-Submission, SQL Server, GDCC แบบ `Integration Placeholder` อย่างโปร่งใส
- **ตั้งค่าระบบ (`/admin/system-config`)**: Idle Timeout, นโยบายจัดเก็บ Log, ระดับ Error Correction ของ QR Code

### 5. Module E: บันทึกประวัติและ Log ระบบ (Audit Log & Security)
- **Audit Logs (`/auditor/logs`)**: บันทึกประวัติการกระทำสำคัญทุกขั้นตอนแบบ Append-Only (Login, Draft, Submit, Approve, Suspend)
- ค้นหา กรองตามประเภทและผลลัพธ์ (SUCCESS, WARNING, FAILED) พร้อมปุ่มเปิดดูรายละเอียดและ **Export Excel/CSV**

## 🧪 สถานการณ์จำลองสำหรับทดสอบ (Seed Data Scenarios)

1. **เคส 1: อาหาร (เผยแพร่แล้ว - Active QR Code)**
   - ชื่อ: *เครื่องดื่มรังนกแท้สำเร็จรูป ตรา เฮลท์โกลด์* (เลขสารบบ: `10-1-04760-5-0012`)
   - URL: `/verify/U1FD0001012345678901234567C`
   - ผลการทดสอบ: แสดงฉลากสมบูรณ์, ตารางโภชนาการ, QR Code สแกนได้จริง, สลับภาษา TH/EN ได้
2. **เคส 2: ยา (รอตรวจ / เอกสารกำกับยา PDF)**
   - ชื่อ: *ยาเม็ดพาราเซตามอล 500 มิลลิกรัม ตรา สยามฟาร์มา* (ทะเบียน: `1A 45/65`)
   - URL: `/verify/U1DR0002012345678901234567C`
   - ผลการทดสอบ: มีข้อบ่งใช้, ข้อห้ามใช้, ปุ่มเปิดอ่านเอกสารกำกับยา PDF ภายในหน้าเว็บ
3. **เคส 3: เครื่องสำอาง (ถูกสั่งระงับ - Suspended Alert)**
   - ชื่อ: *ครีมบำรุงผิวหน้า ไวท์เทนนิ่ง ออร่า โกลว์* (จดแจ้ง: `10-1-6600123`)
   - URL: `/verify/U1CM0003012345678901234567C`
   - ผลการทดสอบ: **แสดงแบนเนอร์แจ้งเตือนอันตรายสีแดง** ระบุคำสั่งระงับของ อย. พร้อมปุ่มแจ้งสายด่วน 1556
4. **เคส 4: ผลิตภัณฑ์เสริมอาหาร (ส่งกลับแก้ไข - Revision Required)**
   - ชื่อ: *น้ำมันปลา โอเมก้า 3 พลัส* (เลขสารบบ: `11-1-08862-5-0034`)
   - ผลการทดสอบ: แสดงข้อความที่เจ้าหน้าที่ อย. สั่งให้ปรับปรุงแก้ไข สามารถแก้ไขและยื่นใหม่ได้

## ☁️ ขั้นตอนการนำขึ้น Vercel (Vercel Deployment Guide)

โปรเจกต์นี้ได้รับการปรับแต่งให้สามารถ Deploy บน **Vercel** ได้โดยอัตโนมัติ:
1. Push โค้ดทั้งหมดขึ้น GitHub
2. ไปที่ [Vercel Dashboard](https://vercel.com) แล้วกด **Add New Project**
3. เลือก Repository นี้ โดย Vercel จะตรวจพบ Vite อัตโนมัติ:
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. ไฟล์ `vercel.json` มีการตั้งค่า SPA Routing Rewrites ให้ทุก URL (เช่น `/verify/:newcode`) ทำงานได้อย่างราบรื่น
